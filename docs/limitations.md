# Known limits

- Bundled client profiles span the selected releases 1.20.4–26.3. Independent launches of all eight presets verify selected menu geometry and ASCII/Latin-1 MOTD cases, including bold, italic, underline, strikethrough and version-specific shadows. Other glyphs and arbitrary style combinations, custom fonts and Bedrock are not claimed pixel exact. See [profiles.md](profiles.md) for the measured scope and references.
- Non-italic Windows font antialiasing remains platform dependent (#70). The selected Linux references use exact masks; Windows regressions verify foreground cell coverage, native shadow anchors and viewer/editor agreement. This is not full raw-pixel parity.
- Unsupported Unicode and decomposed combining sequences produce `missing-glyph` warnings for the bundled font. Browser fallback glyphs and their width estimates can differ from the client. Graphemes remain atomic while editing; this does not certify native shaping. Custom-font and unsupported-glyph italic fallback remains approximate.
- CRLF retains its CR control and LF boundary. The native CR control glyph is not bundled: its display uses `?` with a warning, while source and clipboard retain CR. Empty or multiline protected components require ordinary export rather than materialized layout.
- Default background/icon/button illustrations approximate the client appearance. Original release panoramas and game textures are not shipped. Host-provided assets allow separate configuration; they do not by themselves establish complete pixel accuracy or redistribution permission.
- Optional cubemap backgrounds reproduce the audited Java 26.3 camera pose, face order and rotation rate. Cross-origin faces require anonymous CORS permission; unavailable WebGL or GPU loss retains a static fallback. CSS blur/dimming approximate the native shader post-processing; exact shader blur and original panorama artwork are not included. The standalone examples use original CC0 artwork.
- Bundled `java-ltr` profiles use the measured Java ASCII-space word-breaking rules; custom profiles that omit `font.layout` retain legacy grapheme wrapping. Complex shaping and bidi ordering are outside this LTR capability and produce `unsupported-text-layout` warnings. Extra imported lines and consumed source spaces are retained; only two MOTD lines are visible.
- New inline MOTD edits are limited to two measured display lines, including soft wrapping, bold/proportional widths and resolved values. Over-limit typing, paste and formatting leave the document and undo history unchanged. Source/import can retain longer documents; the fixed viewport does not scroll into hidden rows, and existing overflow can be shortened or explicitly cleared.
- Explicit layout export bakes measured visual breaks and alignment spaces into output. A break inside an unresolved placeholder or protected construct returns `protected-layout`; ordinary export preserves its source instead. Runtime alignment defaults to the 1.21.1 width unless the host supplies `RuntimeContext.motdLayout`; previews supply their actual profile and width.
- Inline gradients and rainbows share the preview's per-glyph color evaluation; see [inline-effects.md](inline-effects.md). Protected unknown components still use their existing approximate visual fallback.
- Unknown MiniMessage/JSON constructs remain protected. Their visual fallback is approximate; cross-format export may require explicit reduction.
- Chromium, Firefox and Playwright WebKit run the automated editing/preview suite; see [browser-verification.md](browser-verification.md). Real Japanese IME, assistive technology and shipping Safari on macOS/iOS still need manual verification. Synthetic composition events alone are not proof of actual IME support.
- Count hover can be unreachable when players are hidden or the version is forced incompatible; diagnostics report this. Minecraft controls the final tooltip behavior.
- No automatic network ping/import or clipboard permission assumptions. The consuming application supplies transport, persistence, permissions and publication.
